Marina del Rey, 1994

Bob Braden of USC's Information Sciences Institute thought one trip was waste. In July 1994 he published RFC 1644, T/TCP. The three-way handshake "adds an extra RTT (round trip time) to the latency of a transaction." So T/TCP skipped it: a server cached a counter per client; a SYN numbered above the cache "must be new and can therefore be accepted immediately", data and all.

Page 38, Security Considerations, in full: "Security issues are not discussed in this memo."

Charles Hannum of the NetBSD Project supplied them in September 1996. The handshake gives "minimal security against spoofing the source IP address": the client must echo the server's initial sequence number, seen only by the real recipient. T/TCP's counter was "even more trivial to predict than the ISS." Forge an address; the server runs the request and logs a stranger.

The IETF's TCP roadmap, Braden a co-author, marked RFC 1644 "found defective": it "floundered on the ease of denial-of-service attacks." RFC 6247 moved it to Historic in May 2011, naming no replacement. Google's TCP Fast Open won the trip back at CoNEXT 2011, projected 15% off HTTP transaction network latency, by paying with "a security token that verifies IP address ownership."

That trip is not ceremony. It is the server's only proof that the asking address is real, and nobody has found a way to get that proof for free.

One cold HTTPS request, half a planet away. List every round trip before the first byte arrives, before you read on.
