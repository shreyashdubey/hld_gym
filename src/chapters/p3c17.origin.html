Berkeley, 1991

Some file systems already had a log. None of them trusted it.

The log was a scratchpad. Write the change there so a crash cannot leave the disk half-updated, then copy it to where the data really lived — a random-access structure, updated in place. Two writes per change.

Mendel Rosenblum and John Ousterhout deleted the second write. In Sprite LFS, "there is no other structure on disk." The index lives inside the log. The payoff: Sprite LFS could use 70% of disk bandwidth for writing, where Unix file systems typically managed 5-10%.

Then the bill. You cannot punch a hole in the middle of a log, so they cut it into segments and ran a segment cleaner that rewrites the live data out of fragmented ones. Keeping free space, they wrote, "is the most difficult challenge in the design of a log-structured file system."

In 1995 Margo Seltzer ran BSD-LFS against the Fast File System on TPC-B. Without the cleaner LFS was "approximately 50% better" than FFS. With it, "any performance advantage of LFS is already lost at a file system utilization of only 48%." Afterward, Ousterhout published a critique of the measurements. Seltzer published a response.

The idea won anyway; LSM trees are named after it. A store whose truth is a log must reclaim its own space, and that work is not a feature you add — it is the rent.

Where does that rent land in a system you have to size? Write it first.
