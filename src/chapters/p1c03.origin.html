IBM San Jose, 1979

Machine time arrived as a bill. Pat Selinger told an interviewer in 2003 that Boeing, an early user of System R, IBM's experimental relational database, said it was February and the year's computing budget was gone. Boeing meant it as praise. Something still had to decide, per query, whether an index beat reading the whole table.

Selinger's team priced every access path in one currency: "index pages fetched plus data pages fetched" plus a weight for CPU. Smallest wins. Pricing an index meant defining how much of one a query could use, so in 1979 they wrote it down: predicates match an index when the columns they name are "an initial substring of the set of columns of the index key".

That is the leftmost-prefix rule: a definition, not folklore. It follows from an index key being a concatenation sorted left to right.

The other half never worked. Pricing needs the row count a predicate returns. Nobody had it. So the paper assumed "an even distribution of tuples among the index key values", multiplied predicates as if "column values are independent", and for an unindexed equality wrote a flat 1/10.

You never choose the plan. You choose the tables and the index column order; the optimizer chooses the rest from those guesses. Its own authors knew the costs came out "often not accurate in absolute value".

Your index is on (city, created_at); the query filters only on created_at. What does the optimizer price? Write it before reading on.
