Palo Alto, 1984

Two Dorados, one wire, one call to cross it.

Andrew Birrell and Bruce Nelson built remote procedure calls for Cedar at Xerox PARC on a rule: the semantics should be "as close as possible to those of local (single-machine) procedure calls". Then they measured it. A call with no arguments took a median 1097 microseconds. Locally, 9.

The gap was not the problem. Retransmission was. A sender retransmits until acknowledged, so the callee sees the same call twice. They put the recogniser in the packet. The caller mints a call identifier — "the calling machine identifier …, a machine-relative identifier of the calling process, and a sequence number" — and the callee keeps "a table giving the sequence number of the last call invoked by each calling activity". Not greater, discarded.

The table costs memory, so an idle server drops the entry "after an interval … (say, after five minutes)" — on the assumption that no retransmission is still in flight.

They printed the ceiling. If the call returns, the procedure ran precisely once. If it does not, it ran "either once or not at all—the user is not told which".

Ten years on, Sun's Jim Waldo drew it out: "The only way to fix this is to change the protocol to add request IDs. But since this is a standardized interface, there is no way to do this."

Pick an endpoint you have shipped. If a client sends it twice, what is true after? Write it down first.
