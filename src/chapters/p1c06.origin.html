IBM System/360, 1968

A fast store no program was allowed to notice.

IBM wanted an 80-nanosecond processor cycle and main storage of 4096K bytes. Core that big ran at 1.04 microseconds. So the Model 85 got 16K bytes of fast store inside the CPU, and a footnote naming it: "The term cache is synonymous with high-speed buffer."

Speed was the easy half. The machine had to run existing System/360 programs unchanged, so filling and discarding the cache "must take place without program assistance".

That one rule writes the write policy. A value living only in the cache would make the machine answer differently depending on hardware the program could not see. So, Liptay: "Store operations always cause main storage to be updated". Every byte in the cache is also in main storage, so dropping a sector moves no data — reset the validity bits and forget it.

It rented for $158,000 a month; that March the census counted zero installed. Transparency held only while the processor was the only writer: channel stores had to be forced down the same path, or the cache would serve a value main storage no longer held. Over nineteen traces the hit probability averaged 0.968; on random addresses it collapses to "much less than 0.01". "What makes the cache work is the fact that real programs are not random in their addressing patterns."
